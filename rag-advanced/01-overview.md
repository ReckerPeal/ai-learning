# 01 · 进阶路线图

## 1. Naive RAG 的天花板

最小 RAG（[langchain/07](../langchain/07-rag.md)）只有一条直线：

```
query ──► embed ──► top-k similarity ──► stuff into prompt ──► LLM ──► answer
```

很快就会遇到这些问题：

| 现象 | 根因 |
|---|---|
| 检索召不回相关文档 | 分块太碎 / 中文 embedding 太弱 / query 表达和文档差距大 |
| 召回了但答非所问 | 没有 reranker，top-k 里相关度乱序 |
| 答案"看起来对但其实编的" | LLM 没真正用上下文，prompt 工程不到位 |
| 多跳问题答不出来 | 一次检索拿不到所有需要的信息 |
| 用户问得模糊 / 口语 | query 没改写就拿去检索 |
| 数值/表格类问题答不准 | 把表格切成文本碎片，结构丢了 |
| 时效性问题答错 | 没有 metadata 过滤、没有时间维度 |
| 上线后越用越慢 / 越来越贵 | 没缓存、没 trim、没分级模型 |

**Naive RAG 在演示数据上能到 70 分，在真实业务里通常停在 40-50 分。** 进阶 RAG 的所有技巧都是在攻这个差距。

## 2. 三代 RAG（综述视角）

学界把 RAG 演进分成三代（Gao et al., 2023）：

### 2.1 Naive RAG

`Index → Retrieve → Generate`，就是上面那条直线。

### 2.2 Advanced RAG

在三个阶段都做优化：

```
索引前/中：               检索阶段：              生成后：
- 分块策略                - Query 改写            - 重排
- metadata 富化           - HyDE                  - 压缩
- 多向量索引              - 混合检索              - 答案校验
                          - Step-back
```

本主题 02-06 章主要讲这一代。

### 2.3 Modular / Agentic RAG

不再是固定流水线，而是**用 Agent 编排可选模块**——根据问题类型决定检索几次、要不要再 query、要不要调工具：

```
classify ──┬─► simple QA           ──► answer
           ├─► need retrieval      ──► retrieve ──► grade ─┬─► good ──► answer
           │                                               └─► bad  ──► rewrite ──► retry
           └─► multi-hop           ──► decompose ──► retrieve×N ──► synthesize
```

这就是为什么**进阶 RAG 几乎一定会用上 LangGraph**——固定 LCEL 链表达不了"必要时重来一次"的循环。本主题 07 章专门讲。

## 3. 路线图：从 Naive 到生产

按投入产出比排序：

| 优先级 | 改动 | 提升 | 成本 |
|---|---|---|---|
| ⭐⭐⭐ | 换中文优化的 embedding | 召回 +20-40% | 重建索引 |
| ⭐⭐⭐ | 加 reranker | 答案准确度 +15-30% | +1 次 API 调用 |
| ⭐⭐⭐ | metadata 过滤（来源/时间/类型） | 噪音 -50% | 索引时多写几个字段 |
| ⭐⭐ | 混合检索（BM25 + 向量） | 长尾查询召回 +10-20% | 多一份倒排索引 |
| ⭐⭐ | Query 改写 / 多 query | 模糊问题召回 +10% | 多 1 次 LLM 调用 |
| ⭐⭐ | 父子文档 / 层级分块 | 答案完整度 +10% | 索引重构 |
| ⭐ | HyDE | 边界 case 召回 | 多 1 次 LLM |
| ⭐ | Self-RAG / CRAG | 大幅减少幻觉 | 复杂度 +++ |
| ⭐ | 多模态（图/表） | 解锁新场景 | 显著工程量 |

**先做前 4 项**，绝大多数项目就足够。再上 Agentic RAG 是给 hard case 兜底的。

## 4. 一个标准的"进阶 RAG"参考架构

```
                            ┌────────────────────────┐
   user query ──► classify──┤ simple? → direct LLM   │
                            │ need_search?           │
                            └────────┬───────────────┘
                                     │
                                     ▼
                       ┌─────── Query 变换 ────────┐
                       │  rewrite / multi-query    │
                       │  HyDE（可选）              │
                       └──────────┬────────────────┘
                                  │
                                  ▼
                       ┌─── Hybrid Retrieval ──────┐
                       │  BM25  +  Vector          │
                       │  + metadata filter        │
                       │  → RRF 合并 top-N         │
                       └──────────┬────────────────┘
                                  │
                                  ▼
                       ┌─────── Rerank ────────────┐
                       │  Cohere / BGE-Reranker    │
                       │  → top-K (4-8)            │
                       └──────────┬────────────────┘
                                  │
                                  ▼
                       ┌─── (Agentic) Grade ───────┐  → 不够好时重检索
                       │  LLM 评估 docs 质量        │
                       └──────────┬────────────────┘
                                  │
                                  ▼
                       ┌────── Generate ───────────┐
                       │  prompt + LLM             │
                       │  + 引用 / 校验             │
                       └──────────┬────────────────┘
                                  │
                                  ▼
                              ┌──────┐
                              │  ✅  │
                              └──────┘
```

## 5. 心智模型转变

| Naive 的思维 | 进阶的思维 |
|---|---|
| "改 prompt 就能修一切" | 70% 的 RAG 问题在**检索**阶段，不在生成 |
| "k=4 拿 top-4 就行" | 召回 → 重排 → 截断，每个环节用不同的 k |
| "LLM 能从上下文里找答案" | 上下文必须**已经被排好序**喂给 LLM |
| "我肉眼看挺好" | 不评测就没法迭代——必须有 golden set |
| "一条链跑到底" | 复杂场景需要**条件分支 + 循环**（→ LangGraph） |
| "向量库选啥都行" | 选型直接决定混合检索 / 过滤 / 性能 |

## 6. 学习顺序建议

按问题驱动：

- **召回不准** → 02 分块 → 03 embedding → 04 混合检索
- **排序不准** → 06 重排 → 04 混合（RRF）
- **query 太模糊** → 05 Query 变换
- **复杂 / 多跳问题** → 07 Agentic RAG
- **要上线** → 09 评测 → 10 生产化
- **特殊数据** → 08 多模态/表格/SQL
